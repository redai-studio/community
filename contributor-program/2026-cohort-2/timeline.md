## 如何参与

1. 从任务列表中选择题目，在对应的 GitHub Issue 下留言认领。
2. 需要 RFC 的任务，先提交方案并通过评审，再进入开发。
3. 提交 PR，关联任务 Issue，并提供题目要求的测试、实验结果或文档。
4. 确保 required CI 全部通过，并通过 `rai-studio-bot` 的自动 Review。
5. 通过问卷提交 Review 请求。
6. 根据 Review 意见继续完善，直到 PR 合入；合入后由导师验收并确认积分。

## 认领方式

在任务对应的 GitHub Issue 下评论，将示例中的 `1` 替换为任务总表中的编号。

**单人认领：**

```text
【报名】1
【GitHub ID】your_github_id
```

**组队认领（2–3 人）：**

```text
【报名】1
【GitHub ID】your_github_id
【组队队友 GitHub ID】teammate_github_id_1、teammate_github_id_2
```

组队时由队长留言，填写本人及所有队友的 GitHub ID。

## 认领规则

- 每人选择单人或组队中的一种方式参加，团队最多 3 人，不能同时以多种方式参与。
- 每道题同时最多由 5 个团队认领。
- 同一团队同时认领且未完成的题目最多 2 个，超出部分认领无效。
- 认领后 7 天内未提交 PR 或 RFC，该次认领作废。
- 每个团队本期最多有 2 次作废机会；超过 2 次后，本期不能继续认领新任务。

## 积分与奖品

本期统一使用 ⭐ 标记任务难度和奖励积分，具体星数见每道任务。

- 完整完成任务并合入全部相关 PR 后，按任务星数记分；一个任务包含多个 PR 时，需要全部合入。
- 如因时间原因未能完整完成，由导师根据已合入的内容确定折算积分；没有任何代码合入不记分。
- ⭐ 可兑换奖池中的奖品，支持跨期累计，最多可累计到后两期。具体奖品及兑换标准待公布。

## RFC 规则

是否需要 RFC 由导师根据任务复杂度确定，以每道任务的标注为准。RFC 是开发方案，以 GitHub Issue 形式提交，标题格式为：`【No.xxx】任务名称 - RFC`。

- 需要 RFC 的任务，导师先 Review 并通过 RFC，再 Review 后续 PR。
- 每道题选出最优方案，由提出该方案的团队锁定开发，其他团队提交的 PR 不进入 Review。
- 入选团队放弃开发后，其他开发者可按无 RFC 任务的认领机制继续认领。
- RFC 入选团队获得由导师确定数量的保底 ⭐；未入选团队无 ⭐。
