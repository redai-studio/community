## 如何参与

1. 从任务列表中选择题目，在对应的 GitHub Issue 下留言认领。
2. 需要 RFC 的任务，先提交方案并通过评审，再进入开发。
3. 提交 PR，关联任务 Issue，并提供题目要求的测试、实验结果或文档。
4. 确保 required CI 全部通过，并通过 `rai-studio-bot` 的自动 Review。
5. 通过问卷提交 Review 请求。
6. 根据 Review 意见继续完善，直到 PR 合入；合入后由导师验收并确认积分。

## 认领方式

在任务对应的 GitHub Issue 下评论，将示例中的 `1` 替换为任务总表中的编号。

**单人认领：**

```text
【报名】1
【GitHub ID】your_github_id
```

**组队认领（2–3 人）：**

```text
【报名】1
【GitHub ID】your_github_id
【组队队友 GitHub ID】teammate_github_id_1、teammate_github_id_2
```

组队时由队长留言，填写本人及所有队友的 GitHub ID。

## 认领规则

- 每人选择单人或组队中的一种方式参加，团队最多 3 人，不能同时以多种方式参与。
- 每个团队须指定 1 名队长，由队长统一负责赛题认领及对接。
- 每道题同时最多由 5 个团队认领。
- 同一团队同时认领且未完成的题目最多 2 个，超出部分认领无效。
- 认领后 7 天内未提交 PR 或 RFC，该次认领作废。
- 每个团队本期最多有 2 次作废机会；超过 2 次后，本期不能继续认领新任务。

## RFC 规则

是否需要 RFC 由导师根据任务复杂度确定，以每道任务的标注为准。RFC 是开发方案，以 GitHub Issue 形式提交，标题格式为：`【No.xxx】任务名称 - RFC`。

- 需要 RFC 的任务，导师先 Review 并通过 RFC，再 Review 后续 PR。
- 每道题选出最优方案，由提出该方案的团队锁定开发，其他团队提交的 PR 不进入 Review。
- 入选团队放弃开发后，其他开发者可按无 RFC 任务的认领机制继续认领。
- RFC 入选团队获得由导师确定数量的保底 ⭐；未入选团队无 ⭐。

## 发星与兑换规则

### 1. 按团队发星

星星按团队发放。例如，一道 8 星任务完成后，整个团队共获得 8 星，不因团队人数增加而翻倍。

**每道题最终仅允许一个成果合入，并且只发放一次星星。**

每期活动结束后统一核验；最终成果完成合入且通过验收后，星星一次性记入对应团队账本。

团队账本记录星星的来源期次、来源任务、获得时间、到期时间和已兑换状态。

### 2. 等值兑换与跨期累计

**所有星星等效，可跨题、跨期自由累计。** 完成多个低星任务获得的星星也可以累计兑换高星档奖品。

每期活动结束并完成发星后，统一开放当期兑换窗口；活动进行中不单独采购或发放奖品。

第 N 期获得的星星，可在第 N、N+1、N+2 期的兑换窗口使用；第 N+2 期兑换窗口关闭后自动失效。兑换时优先扣除最早到期的星星。

每件奖品按所在档位扣除固定星数；组合兑换时，各奖品所需星数相加。4 星和 6 星暂无专属奖品，可组合兑换其他档位。

### 3. 队长负责制与兑换核销

**每个团队须指定 1 名队长，主办方仅与队长对接。** 队长统一负责赛题认领、进度同步、成员变更、兑换申请、奖品选择、收件信息及队内协调。

**队长提交即视为团队已达成一致；主办方仅与队长对接。** 发生争议时暂停兑换，由团队内部协商解决。

星星归属于团队账本，不归队长个人所有；团队成员加入或退出不拆分、不复制历史星星。

队长发生变更时，由原队长完成交接；原队长无法履职时，由现有成员形成一致意见并提交证明。

每次兑换生成唯一兑换记录，先核销团队星星，再进入采购和发奖流程；已核销星星不得重复使用。

**星星不得出售、赠送或跨团队转移；团队合并不自动合并星星余额。**
